Adding Nodes (Node Picker)

A new project starts with an empty canvas. Nodes are added one at a time from the Node picker, a searchable tree of every node provided by the loaded modules.

It is implemented in src/editor/ui/node_picker.hpp and src/editor/ui/node_picker.cpp, and wired in Application::BuildMenus() and Application::ProcessInput() (src/editor/application.cpp).

Opening it​

FromWhere the picker opensWhere the node appears
Top bar: Node > Add NodeUnder the Node titleCentre of the view (shifted when a node is already there)
Shortcut Shift+A (node.add_menu action)At the mouse cursorCanvas position under the cursor when the picker was opened

Both open the same list.

Using it​

Without a search the picker shows a tree, like Unity's Shader Graph:

  • one folder per module, then the module's category folders. A node with the category "Flow/Loops" sits in C > Flow > Loops; a node without category sits directly in its module folder. Sub-folders come before nodes, in the order of first appearance.
  • Folders start closed; when only one module is loaded its folder starts open. A click or Enter toggles a folder, Right opens it (or enters it when open), Left closes it (or goes up to the parent folder).

Typing a search replaces the tree with a flat list of the matching nodes, without folders: case-insensitive substring of the node name (folder names are not searched), names starting with the text first. Closed folders do not hide results. Clearing the search brings the tree back as it was.

In both modes:

  • Up/Down move the selection, the mouse wheel scrolls, moving the mouse over a row selects it. In the flat list the first result is selected, so typing then Enter creates it.
  • Enter or a click on a node creates it. Escape or a click outside closes the picker without creating anything.
  • Each pick creates exactly one node and closes the picker. The created node becomes the selection, so it can be moved right away.
  • The box keeps the same size while folders open or a search is typed.

While the picker is open it owns the mouse and the keyboard: shortcuts (Delete, Ctrl+C, Shift+A, ...) are ignored so that typing a search never edits the graph.

The character of the shortcut that opened the picker is never typed into the search: it can arrive one frame after the key press (Windows) and repeats while the key is held. The picker ignores typed characters on its first frame and until the shortcut key (ActionManager::IsShortcutKeyDown("node.add_menu"), AZERTY included) is released; after that, every key types normally.

Categories​

A module gives the folder of each node with NodeMetadata::category_ (folders separated by /). With the generic capa::NodeListCapability, pass it as the last argument of RegisterNode(name, description, config, category); it defaults to empty. The catalog exposes it as NodeDescriptor::category_ (and the description as NodeDescriptor::description_).

The C module uses: Data (Variable, Literal), Math (Operator), Flow (Condition), Flow/Loops (Loop, For), Functions (Function, FunctionInput, FunctionOutput), IO (Print).

Where the list comes from​

Application::LoadModule() refreshes the core::NodeCatalog, which assigns the node type ids, then gives the picker its entries with ui::EntriesFromCatalog(). No node is created at startup.

When a node is picked, Application::CreateNode() looks the type up in the catalog, asks the module that provides it for a fresh NodeConfiguration (INodeListCapability::GetNodeConfiguration), and builds the node from it: pins and the module's default property values. Each node gets its own copy of the defaults, so several instances of the same node never share values.

Testing​

tests/editor/node_picker_test.cpp drives the picker through NodePickerInput with a fixed-width text measurer, without a window: tree building, folders opening and closing (mouse and keyboard), flat search, picking, closing, scrolling, and the conversion from the catalog of the C module.
