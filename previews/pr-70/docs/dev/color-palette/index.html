Color Palette

Every color the editor draws with is named in one file: src/utils/palette.hpp. No color is written as numbers anywhere else: the code references the palette by name, so changing a color in the palette changes it everywhere it is used.

Referencing a color​

Colors are grouped by the part of the editor they belong to:

#include "utils/palette.hpp"

ClearBackground(palette::canvas::kBackground);
utils::DrawRectangleRecWrapped(bar, palette::top_bar::kBackground);
SectionUsed by
palette::chasmThe Chasm palette of the design (see below)
palette::baseColors shared by several sections
palette::canvasCanvas background, grid, rectangle selection
palette::top_barMenu bar and its drop-down menus
palette::popupNode picker, drawn like a node card
palette::nodeNode cards: header, body, title, pin names
palette::fieldValues and settings drawn inside the nodes
palette::linkSelected link, link being dragged
palette::notificationWarnings at the bottom of the window
palette::typePins and links, by data type
palette::accentLine at the top of the nodes, by kind of node

Adding a color​

Add one line in the right section, from the hex code of the design and an optional opacity (from 0 to 1):

namespace canvas {
inline constexpr utils::WrappedColor kBackground = Hex(0x23252D);
inline constexpr utils::WrappedColor kGrid = Hex(0x2E3037);
inline constexpr utils::WrappedColor kMyColor = Hex(0x76A0E0);       // new
inline constexpr utils::WrappedColor kMyShadow = Hex(0x000000, 0.25F);  // new
}  // namespace canvas

A color can reuse another one (kDropdown = top_bar::kBackground) or another one with a different opacity (WithOpacity(base::kAccent, 0.12F)). Colors are constexpr: they cost nothing at run time.

Pin types​

Pins and links take the color of their data type, looked up by the name the module gives the type:

TypeColor
intblue
floatviolet
stringgreen
boolred
custom (user defined)orange
any other (char...)grey
void (execution flow)silver, drawn as a triangle
inline constexpr Entry kColors[] = {
    {kFlowTypeName, kFlow}, {"int", kInt}, {"float", kFloat},
    {"string", kString}, {"bool", kBool},
};

palette::TypeColor("int");           // type::kInt
palette::TypeColor("char");          // type::kOther (grey)
palette::TypeColor("Player", true);  // type::kCustom (orange)

No module declares custom types yet: is_custom is there for when one does. A pin without a link is hollow.

Node accents​

The line at the top of a node (and the marker before its name in the node picker) tells what kind of node it is:

ColorNodesRule
RedEntry points: Function, its input/outputcategory Functions
WhiteBranches (Condition) and loopscategory Flow, Flow/...
BlueNodes that set a variablenode Variable
NoneEverything else

A node is first looked up by name (accent::kNodes), then by the root folder of its category (accent::kCategories):

palette::NodeAccent("Variable", "Data");   // accent::kVariable (blue)
palette::NodeAccent("For", "Flow/Loops");  // accent::kBranch (white)
palette::NodeAccent("Literal", "Data");    // accent::kNone (no line)

The nodes get the type names, accents and links through ui::NodePaint, given once by the application with NodeCanvas::SetPaint().
